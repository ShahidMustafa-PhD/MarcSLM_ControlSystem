## WHY IT HAPPENED AT LAYER 7/8 SPECIFICALLY

### Timing Drift Accumulation

Each layer cycle has small timing variations:
- Polling interval: 500ms (not perfectly synchronized)
- Layer prep time: 5000ms (fixed)
- Scan execution time: Variable (200ms - 2000ms depending on geometry)

**Cumulative drift after N layers:**
```
Layer 1: +0ms offset
Layer 2: +50ms offset
Layer 3: +120ms offset
Layer 4: +200ms offset (previous halt - different bug)
Layer 5: +280ms offset
Layer 6: +370ms offset
Layer 7: +450ms offset ? Close to 500ms polling window!
Layer 8: +530ms offset ? MISS THE FALLING EDGE!
```

When drift exceeds ~500ms, polling **misses the falling edge** (TRUE ? FALSE transition), causing `mPreviousPowderSurfaceDone` to stay TRUE permanently.

### Why the Fix Eliminates Drift Dependency

? **Explicit resets** ensure state is always clean  
? **Defensive reset** at layer start provides double safety  
? **No reliance on falling edge detection** for state reset  
? Works regardless of polling interval or timing drift  

---

**CONCLUSION:** The Layer 7/8 halt was caused by **incomplete state reset** in the OPC handshake, exacerbated by **timing drift** after multiple layers. The fix explicitly resets both handshake flags on layer completion, ensuring clean state for all subsequent layers.
